## БЛОК 1: Основы функционального программирования (0–20 мин)

### Конспект теории

#### 1. Что такое функциональное программирование (2 мин)

ФП — парадигма, где программа — это набор функций-трансформаций данных, а не объектов с состоянием.

Главный принцип: **функции не меняют мир — они возвращают новые значения**.

В отличие от ООП, где объект несёт в себе состояние и методы его меняющие, в ФП функции — чистые «черные ящики»: одинаковый вход всегда даёт одинаковый выход.

```
// ООП мышление
class Counter {
  count = 0;
  increment() { this.count++; }
}

// ФП мышление
const increment = (n: number): number => n + 1;
```

#### 2. Чистые функции (3 мин)

**Определение:** функция чистая, если:
1. **Детерминирована** — при одних и тех же аргументах всегда возвращает одно и то же значение
2. **Без побочных эффектов** — не меняет ничего снаружи себя

**Что делает функцию нечистой:**
- `Math.random()`, `Date.now()` — не детерминированы
- `console.log()`, изменение DOM, запрос к API — побочные эффекты
- Мутация аргументов или глобального состояния

```typescript
// Нечистая: зависит от Date.now(), пишет в консоль
function logGuess(guess: string): string {
  console.log(`[${Date.now()}] Попытка: ${guess}`);
  return guess;
}

// Чистая: только аргументы, только return
function formatGuess(guess: string, timestamp: number): string {
  return `[${timestamp}] Попытка: ${guess}`;
}
```

**Почему важно для тестирования:** чистую функцию можно проверить без моков, без setup/teardown, без зависимости от окружения. Это и есть основа TDD.

---

#### 3. Иммутабельность (2 мин)

**Правило:** не меняй переданные данные — создавай новые.

```typescript
// Мутация — плохо
function addGuess(history: string[], guess: string): string[] {
  history.push(guess); // меняет оригинальный массив!
  return history;
}

// Иммутабельно — хорошо
function addGuess(history: string[], guess: string): string[] {
  return [...history, guess]; // новый массив
}
```

```typescript
// Мутация объекта — плохо
function updateSettings(state: GameState, base: number): GameState {
  state.base = base; // мутация!
  return state;
}

// Иммутабельно — хорошо
function updateSettings(state: GameState, base: number): GameState {
  return { ...state, base }; // новый объект
}
```

Иммутабельность даёт бесплатно: история изменений, easy undo/redo, predictable UI rendering, отсутствие shared mutable state.

#### 4. Функции высшего порядка (HOF) (3 мин)

Функция, которая **принимает функции как аргументы** или **возвращает функцию**.

Три кита: `map`, `filter`, `reduce`.

```typescript
const numbers = [1, 2, 3, 4, 5];

// map: трансформирует каждый элемент
const doubled = numbers.map(n => n * 2); // [2, 4, 6, 8, 10]

// filter: оставляет элементы, где предикат true
const evens = numbers.filter(n => n % 2 === 0); // [2, 4]

// reduce: сворачивает массив в одно значение
const sum = numbers.reduce((acc, n) => acc + n, 0); // 15
```

**Цепочки HOF — мощный инструмент:**
```typescript
const result = [1, 2, 3, 4, 5]
  .filter(n => n % 2 !== 0)   // [1, 3, 5]
  .map(n => n * n)             // [1, 9, 25]
  .reduce((acc, n) => acc + n, 0); // 35
```

В задании `evaluateGuess` должен считать bulls и cows именно через HOF, а не через `for` с ручными счётчиками.

#### 5. Рекурсия (3 мин)

**Определение:** функция вызывает сама себя для решения подзадачи.

Два обязательных элемента:
- **Базовый случай** — когда прекратить вызовы
- **Рекурсивный шаг** — задача меньшего размера

```typescript
// Факториал: 5! = 5 × 4 × 3 × 2 × 1
function factorial(n: number): number {
  if (n <= 1) return 1;           // базовый случай
  return n * factorial(n - 1);   // рекурсивный шаг
}

factorial(5); // 5 * factorial(4) = 5 * 4 * 3 * 2 * 1 = 120
```

**Визуализация стека вызовов:**
```
factorial(5)
  5 * factorial(4)
    4 * factorial(3)
      3 * factorial(2)
        2 * factorial(1)
          1  ← базовый случай
```

В задании: `countPossibleSecrets` — сколько уникальных секретов существует = P(base, length) = base × (base−1) × … × (base−length+1). Это натурально записывается рекурсивно.

#### 6. Каррирование (3 мин)

**Определение:** преобразование функции от нескольких аргументов в цепочку функций, каждая из которых принимает один аргумент.

```typescript
// Обычная функция
function add(a: number, b: number): number {
  return a + b;
}

// Каррированная
const curriedAdd = (a: number) => (b: number) => a + b;

const add5 = curriedAdd(5);  // специализированная функция
add5(3); // 8
add5(10); // 15
```

**Практический смысл — частичное применение:**
```typescript
// Фабрика: даёт специализированную функцию под конкретный контекст
const createMultiplier = (factor: number) => (value: number) => value * factor;

const double = createMultiplier(2);
const triple = createMultiplier(3);

[1, 2, 3].map(double); // [2, 4, 6]
[1, 2, 3].map(triple); // [3, 6, 9]
```

В задании: `createDigitValidator(base)` — по системе счисления возвращает предикат. Один раз создал — используй в двух местах: в валидации попытки и в фильтрации ввода.

#### 7. Мемоизация (2 мин)

**Определение:** кеширование результата чистой функции по её аргументам. Второй вызов с теми же аргументами возвращает кешированный ответ без вычислений.

```typescript
function memoize<Args extends unknown[], R>(
  fn: (...args: Args) => R
): (...args: Args) => R {
  const cache = new Map<string, R>();
  return (...args: Args) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key)!;
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

const expensiveCalc = memoize((n: number) => {
  // дорогое вычисление
  return n * n;
});

expensiveCalc(42); // вычисляется
expensiveCalc(42); // из кеша — мгновенно
```

Мемоизация работает только для **чистых функций** — именно потому, что одни и те же аргументы гарантированно дают один и тот же результат.

В задании: `countPossibleSecrets` вызывается при каждом открытии настроек. Значения настроек конечны (length 2–6, base 2/8/10/16) — кешировать их все смысл есть.

**2г. Написать реализацию через HOF (3 мин)**

```typescript
// src/core/evaluateGuess.ts — РЕАЛИЗАЦИЯ
export function evaluateGuess(
  secret: string,
  guess: string
): { bulls: number; cows: number } {
  const s = secret.toLowerCase().split('');
  const g = guess.toLowerCase().split('');

  // Bulls: позиции совпадают — reduce как счётчик
  const bulls = s.reduce(
    (count, char, i) => count + (char === g[i] ? 1 : 0),
    0
  );

  // Cows: считаем пересечение множеств минус bulls
  // Для каждой цифры берём min(сколько раз в secret, сколько раз в guess)
  const countChars = (chars: string[]): Record<string, number> =>
    chars.reduce<Record<string, number>>(
      (acc, c) => ({ ...acc, [c]: (acc[c] ?? 0) + 1 }),
      {}
    );

  const secretCounts = countChars(s);
  const guessCounts = countChars(g);

  const commonChars = Object.keys(secretCounts).reduce(
    (total, c) => total + Math.min(secretCounts[c], guessCounts[c] ?? 0),
    0
  );

  return { bulls, cows: commonChars - bulls };
}
```

**Объяснить вслух алгоритм:**
1. Bulls — `reduce` по позициям, +1 если `s[i] === g[i]`
2. Cows — подсчитать частоту каждого символа в secret и guess (`countChars` через `reduce`)
3. `commonChars` = для каждого символа берём `min(в secret, в guess)` — это все совпадения
4. `cows = commonChars - bulls` — убираем те, что уже посчитаны в bulls

**2д. Тесты зеленеют (30 сек)**

Отметить: ни одного `for`, ни одного `i++`, ни одного ручного счётчика — только `reduce`, `filter`, spread объекта.

```typescript
export function countPossibleSecrets(length: number, base: number): number {

  const key = `${length}:${base}`;
  if (cache.has(key)) return cache.get(key)!;      // мемоизация
  const result = base * countPossibleSecrets(length - 1, base - 1); // рекурсия
  cache.set(key, result);
  return result;
}
```

#### generateSecret.ts

```typescript
export function generateSecret(
  length: number,
  base: number,
  random: () => number = Math.random
): string {
  const pool = '0123456789abcdef'.slice(0, base).split('');

  function pick(remaining: string[], count: number): string[] {
    if (count === 0 || remaining.length === 0) return [];
    const idx = Math.floor(random() * remaining.length);
    const chosen = remaining[idx];
    const rest = remaining.filter((_, i) => i !== idx);
    return [chosen, ...pick(rest, count - 1)];
  }

  return pick(pool, length).join('');
}
```

#### evaluateGuess.ts

```typescript
export function evaluateGuess(
  secret: string,
  guess: string
): { bulls: number; cows: number } {
  const s = secret.toLowerCase().split('');
  const g = guess.toLowerCase().split('');

  const bulls = s.reduce(
    (count, char, i) => count + (char === g[i] ? 1 : 0),
    0
  );

  const countChars = (chars: string[]): Record<string, number> =>
    chars.reduce<Record<string, number>>(
      (acc, c) => ({ ...acc, [c]: (acc[c] ?? 0) + 1 }),
      {}
    );

  const guessCounts = countChars(g);

  const commonChars = Object.keys(secretCounts).reduce(
    (total, c) => total + Math.min(secretCounts[c], guessCounts[c] ?? 0),
    0
  );

  return { bulls, cows: commonChars - bulls };
}
```

## БЛОК 3: Ответы на вопросы (40–60 мин)

### Вероятные вопросы и короткие ответы

**Q: Почему Vitest, а не Jest?**  
A: Vitest нативно понимает ES-модули и TypeScript без дополнительной настройки. Jest с NodeNext требует `ts-jest` и дополнительного конфига. На этой неделе нет бандлера — Vitest проще.

**Q: Почему импорты с `.js` если файл `.ts`?**  
A: При `module: NodeNext` TypeScript резолвит импорты так же, как Node.js — он ожидает, что в рантайме будут `.js` файлы. `tsc` компилирует `.ts → .js`, поэтому в исходниках пишем `.js` уже сейчас. Это не ошибка, это требование NodeNext.

**Q: Зачем передавать `random` параметром в `generateSecret`?**  
A: Чтобы функция осталась чистой и тестируемой. `Math.random()` нарушил бы детерминированность — тест не мог бы проверить конкретный результат. Паттерн называется «dependency injection».

**Q: Splice в `evaluateGuess` — это не мутация?**  
A: Именно поэтому в реализации выше мы используем `countChars` + `min` подход — без мутации. Splice — ловушка для новичков именно в этом месте.

**Q: Как Husky работает в монорепозитории?**  
A: В монорепозитории курса Husky выставляет хуки на весь репозиторий. Студенты работают в своём отдельном репозитории — там проблем нет. На лекции это не важно.

**Q: Нужен ли DESIGN.md для получения баллов?**  
A: Да, это 20 баллов из 150. Писать его последним, когда код стабилен. Не абстрактно — с конкретными именами файлов и функций.

**Q: Что делать с `localStorage` если его нет в тестах?**  
A: Тесты для `localStorage` пишем отдельно (или не пишем — в требованиях он не в списке обязательных функций для TDD). Либо мокаем `localStorage` в Vitest через `vi.stubGlobal`. Важно: `leaderboard.ts` живёт в `src/storage/`, не в `src/core/` — core-тесты его не видят.
